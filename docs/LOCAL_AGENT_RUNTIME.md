# 双模式与本地 Agent Runtime

更新时间：2026-10-27。本文记录当前实现。独立Electron交互与后端回归已检查；真实外部服务、全部账号/课程及安装包没有全量验收。

## 使用入口

1. 按原启动方式打开智小理；修改源码后需要重新启动应用。
2. 在聊天输入区上方选择“校园业务”或“通用学习”。首次仍默认校园业务，之后记住最近选择。
3. 切到通用学习后，点击设置，进入“通用学习”填写厂家、兼容接口地址、模型和API Key，点击固定页脚“保存更改”。长期记忆共用设置中的“长期记忆”开关、学生资料、摘要及独立百炼配置。
4. 可先尝试普通学习问答，再问“现在是几号几点”“今天有什么课”。课表工具读取已有的本机确认课表，没有课表时会返回不可用，不会伪造课程。

千问、DeepSeek为配置预设，使用公共示例地址与模型名称；需按自己的账户、地域、业务空间及模型权限调整。选择“其他兼容接口”可配置其他支持Chat Completions工具调用格式的服务。非兼容原生协议未适配；此处没有承诺所有厂家或所有模型都能调用工具。

2026-10-27：密钥独立保存在userData/config.json，设置页明文回显，可直接修改、复制；清空并保存即删除，不再读取ZXL_STUDY_API_KEY。切换厂家会清空页面旧Key，须填写对应新Key。主进程只向设置页返回明文；聊天页和广播只获得配置状态。未实现系统凭据库加密，不借用校园、记忆或课表识别的密钥。

## 模式与任务归属

校园链：聊天页面 → IPC → 原校园平台服务 → 学校Agent平台与业务工具。

通用链：聊天页面 → IPC → LocalAgentRuntime → 模型兼容适配 → 本地工具 → 工具结果回传模型 → 回答。

- 两种模式共用人物、气泡、设置窗口和朗读；没有修改人物素材或动作参数。
- 每个模式各保留一个当前会话和一个进行中的请求。切换模式不取消原请求，旧模式的回答不插入当前聊天、不自动朗读；切回时显示该模式最近三条消息。
- “停止请求”仅停止当前模式。本地首批工具都是只读；校园停止仍只能停止等待，远端预约操作可能已执行，原不确定结果提示保留。
- “新会话”仅清空所选模式的当前上下文。共享长期记忆和已完成业务不受影响。应用退出停止两边请求。
- 两种模式在新进程首次取得各自会话时均新建会话，不恢复旧会话上下文；同一进程内切换模式、刷新页面不会再次重置。不同模式的消息、工具结果和平台会话ID不混用。

## 本地上下文

`study-session.json`保存当前会话ID、有限展示消息、完整成功轮次及工具执行摘要。成功轮次包含用户消息、模型工具调用、对应tool结果和最终回答；部分兼容模型要求回传的`reasoning_content`仅作为协议上下文保留，不显示、不写入调试日志。

默认向模型发送最近12个成功轮次，最多按30轮配置，同时受48000字符的历史预算约束；按完整轮次从近到远选取，不拆散工具调用与返回。单次请求另有180000字符上下文上限。磁盘成功历史最多30轮且有累计长度上限；本轮是有界近期上下文，不是无限历史、自动摘要或向量检索。

失败/取消轮次不会作为成功历史发送到下一次模型请求。工具失败本身可以作为结构化结果让模型解释，最终完成回答后仍可形成成功轮次。崩溃遗留pending在下次进程读取时变为中断提示，然后按启动规则新建会话。

长期记忆已按用户更正接入。两种模式共用`campus-memory.json`、开关、资料/摘要及百炼整理配置，普通会话仍分别维护。

- 启用时，新会话首条消息前尝试整理待处理问答，独立25秒上限，不占后续模型/工具阶段超时；失败时提示并使用已有记忆。
- 每次通用请求读取当前资料/摘要，经`memoryContext`加入Runtime系统背景，明确是资料而非操作授权，不存入普通轮次。关闭后不注入，编辑后下次请求更新；当前对话已提过的信息可能仍在近期上下文，需新建会话清空。
- 成功回复后，用户原始问题和最终回答加入共享待整理队列，按原阈值后台整理；不含注入背景、工具原始结果、参数或推理正文。
- 关闭时不记录新问答。新会话/重启只重置普通上下文，长期记忆和待整理队列保留。旧版本尚未接记忆的学习历史不会自动补采。
- 记忆整理使用独立百炼配置，不随通用聊天厂家切换。手动资料无整理密钥也可注入，自动整理需原记忆配置有效。

双方也可读取同一份已确认课表，但校园每轮注入课表，通用模式按需调用工具。详见[CAMPUS_MEMORY.md](CAMPUS_MEMORY.md)。

## 工具契约

| 工具 | 参数 | 数据来源与结果 |
| --- | --- | --- |
| get_current_time | 空JSON对象 | 本机时钟换算Asia/Shanghai，返回日期、时间、星期；电脑时间本身需正确 |
| get_timetable | 可选date，YYYY-MM-DD | 本机已保存且启用的个人课表；未传日期返回完整表，传日期按星期/周次筛选候选，附更新时间、学期范围及资料缺失提示 |
| list_homework | 必填course，可选course_key | 本地配置账号登录学习通，查询一个明确课程的作业名称、页面状态、进度；多候选时先确认，不提供截止时间 |

缺少起始周日期、课程周次或星期时，保留待核对候选并说明不确定，不能当成已经确认无课。课表关闭/缺失、读取失败、参数错误与未知工具均返回明确错误。工具结果长度超限返回错误，不把截断列表冒充完整数据。

扩展能力应在工具层注册名称、说明、参数和执行器，让Runtime保持通用循环。需要多次查询时可以继续调用；当前最多8个单批调用、总16次工具调用、默认6次模型请求和120秒总时长（可在设置内调整），达到上限明确失败，不无限循环。无盲重试或任意Shell执行。

新增写操作前需明确权限、确认与幂等策略；当前工具集没有作业/预约等写操作，也没有用模型提示词代替执行器限制。学习通已按用户Java实现移植，使用本地账号配置、内存Cookie及动态签名读取指定课程；用户已反馈可用，不把“查询失败”解释为“没有作业”。详见[CHAOXING_TOOL.md](CHAOXING_TOOL.md)。

## 工程边界

当前仍是Electron + 原生页面 + CommonJS，Runtime独立成模块，由主进程调用，没有新增HTTP服务、额外框架或依赖。以后需要浏览器任务或更重执行器时，可以迁到独立进程，保持消息与工具契约。

模型请求使用兼容Chat Completions的完整JSON响应，本轮只有阶段进度，没有逐token流式正文。千问使用`enable_thinking: false`，DeepSeek使用`thinking: {type: 'disabled'}`；自定义厂家不附加上述厂家参数。接口循环参考[百炼Function Calling文档](https://help.aliyun.com/zh/model-studio/qwen-function-calling)；DeepSeek预设按[官方工具调用示例](https://api-docs.deepseek.com/guides/tool_calls/)填写`https://api.deepseek.com`和`deepseek-flash`，仍需账户实际支持。HTTPS正常校验证书；仅本机localhost/回环地址允许HTTP，禁止URL内账号、查询参数与自动重定向。

复用现有调试日志，事件携带mode/sessionId/requestId，记录模型请求元信息、工具执行名称/耗时/成功状态与最终回复；新密钥加入原有脱敏列表。不记录原始工具调用参数、完整模型响应或推理正文。完整协议历史仍保存在独立本机会话文件。

代理本轮仅完成源码和文档，未测试、编译、构建、启动应用或调用真实模型/校园业务。没有修改已保存用户配置，没有生成新安装包。用户体验反馈与适用范围按阶段总结记录，不扩大为全量验收。
