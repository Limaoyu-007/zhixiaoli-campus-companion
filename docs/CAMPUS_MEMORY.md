# 智小理本地长期记忆第一版

2026-10-24更新。校园平台负责校园模式聊天与业务工具；通用学习由本地Runtime直接连接聊天模型。两种模式共用百炼整理的本机长期记忆，每台电脑使用一份本地档案，不分析性格、品质或人格。

最新接入：通用学习启用时读取同一份资料/摘要，成功问答追加同一待整理队列，重启也新建会话，长期记忆保留。新学习会话首条消息前尝试整理旧对话，每次请求重新读取记忆背景传给Runtime，不混入普通历史。旧版尚未接记忆的学习对话不会自动补采。本轮仅修改源码与说明，未调用模型或运行测试/构建。校园首次注入机制仍保持原样；下文首次注入、不做中途补发等约定仅描述校园模式。

## 使用

1. 关闭旧源码程序，用根目录 `start.js` 或上级目录的启动脚本重新打开。
2. 打开设置的“长期记忆”，填写百炼 API Key，以及控制台对应地域的 OpenAI 兼容接口地址，点击固定页脚的“保存更改”。默认模型为 `qwen-flash`，默认每3轮完整对话整理一次。2026-10-27起，API Key在设置中明文回显，清空后保存即删除；不读取 `DASHSCOPE_API_KEY`，与校园、通用学习和课表识别凭据独立。
3. 正常聊天即可积累资料。可以在设置中查看、编辑资料和近期事项摘要，点击“立即整理”处理不足3轮的对话。修改后点击“新会话”使用最新记忆。

也可以先手动填资料，统一点击“保存更改”；没有百炼凭据时，手动资料仍可带入学校对话，自动整理暂不可用。2026-10-23后续已统一设置页，不再单设“保存记忆”按钮。“立即整理”发现未保存修改时，会先执行同一保存流程再整理。

接口地址可填写 `https://dashscope.aliyuncs.com/compatible-mode/v1`，也可以填写控制台提供的业务空间专属地址。支持填写完整的 `/chat/completions` 地址。只接受HTTPS，不需要额外安装SDK。自定义模型须支持非思考模式、非流式调用及JSON输出。

2026-10-23实测补充：用户使用普通百炼Key，在确认北京地域业务空间专属地址后明确表示“可以了，我也跑通了”。专属地址格式为 `https://llm-<业务空间ID>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`；具体空间与Key使用用户自己的配置，不在本文记录。此处仅确认用户报告整理调用成功，不代表所有信息抽取、跨重启记忆及平台使用效果均已专项验收。

参考：[百炼OpenAI兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[千问结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。具体地域、开通状态和Key以用户自己的百炼控制台为准。

## 启动与会话

- 每个新进程第一次取得会话时，保留本机平台user标识，新建本地会话ID并清空平台conversation_id。页面刷新、反复打开设置不会再次重置。上次远端操作结果不确定的提示仍保留。
- 长期记忆独立于conversation_id。重启和点击“新会话”均不清空长期记忆，也不撤销业务预约。
- 新会话首条真实消息发送前，尝试整理尚未处理的旧对话，然后把资料和摘要作为有边界的背景文本拼到当前问题前。没有记忆时原样发送问题；同一平台会话后续消息不重复注入。
- 首条消息可能额外等待一次记忆整理，单次25秒超时；整理失败则沿用已有记忆继续聊天。不开启中途动态补发、向量检索或多用户切换。
- 后台分析输入为用户原始问题与助手正文，不是附加档案后的平台query，不包含原始工具事件。界面气泡和普通会话记录也保留真实用户问题。
- 后续已加入[个人课表](CAMPUS_TIMETABLE.md)：课表和当前时间每次聊天附上，原文件不发学校平台；记忆整理仍不输入这份自动拼接的课表背景。

## 本地数据与整理

`app.getPath('userData')/campus-memory.json` 独立保存：

- `facts`：用户名字、用户称呼、学校、专业、年级、校区、兴趣爱好、交流偏好、学习偏好。每项含key、value和更新时间；新建/改写的模型事实须带本批用户消息中的原文证据，助手猜测不能作为证据。
- `summary`：最多300字的近期事项摘要。
- `pendingHistory`：尚未整理的对话，原子写盘；等待配置或模型不可用时保留最近40轮，每条用户消息最多4000字、助手消息最多2000字。常见密码/密钥字段做文本脱敏，提取提示词禁止将密码、密钥、预约号或即时业务状态写进长期记忆。
- `lastSummaryAt`、`totalRounds`：更新时间与累计记录轮数。

正常回复完成后追加一轮。达到阈值后发起独立百炼调用，输入已有摘要、已有资料及待整理对话，要求返回JSON。原 `memory-service.js` 的存储结构、事实合并和后台摘要流程继续使用，两种模式通过主进程的共享记忆入口使用 `configure()` 配置；旧版未使用的模型上下文与导入/导出接口已移除。

新会话前的整理包含短对话尾部；后台请求期间新追加的记录保留给下一次整理。请求失败或JSON不合格不清除旧记忆与待处理对话，不自动无限重试。退出时取消整理请求，已落盘记录在下次新会话首条消息前继续处理，不等待网络阻塞退出。

编辑或清空记忆会取消旧分析、丢弃尚未整理的旧记录，防止迟到结果或旧记录恢复已删除内容。不会删除普通会话文件或撤销预约；已发给学校平台的当前会话背景无法从本机撤回，修改后的资料在新会话使用。

## 代码入口

- `services/memory-service.js`：本地文件、后台提取、资料合并、首次注入文本、编辑与清空。
- `services/campus-session-store.js`：每次进程启动新建会话，保留平台用户标识和必要的不确定结果提示。
- `main.js`：独立百炼配置、首条背景拼接、正常回复后记录、记忆IPC与退出取消。
- `preload.js`、`renderer/campus-settings.*`：配置、资料编辑、整理状态和手动整理。
- `config.example.json`、`package.json`：配置模板与模块打包清单，不包含真实Key或用户资料。

代理没有运行测试、构建或额外百炼/学校接口调用；后续用户自行测试，记忆整理成功以用户明确反馈为依据。此前HTTP 401已按用户反馈跑通，不继续记录为当前阻塞。代码已补充401专用提示，以及接口、Key来源/格式、百炼错误码和请求ID的开发日志，均不记录密钥明文。完整抽取准确性和学校平台使用背景的效果没有单独验收结论。
